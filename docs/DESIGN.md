# StateBit 设计

## 应用入口与搜索流程

`Sequential/main.cpp` 和 `Parallel/main.cpp` 调用同一个 `statebit_application()`，仅传入执行方式。`core/application.cpp` 是唯一的核心编译单元，组合配置、预处理、搜索上下文、调度与输出；两个入口链接同一核心对象。

`core/runtime/enumerate_graph.inc` 展示完整的图枚举流程：

1. 剥离无法达到规模阈值的顶点，并构造退化序与根任务。
2. 为工作线程准备搜索存储和上下文。
3. 构造根任务的局部邻域、约束矩阵及极大性检查器，执行搜索。
4. 发布、恢复和消费可迁移任务；在释放根任务存储前排空依赖该存储的后代任务。
5. 汇总各线程结果与统计，释放图和工作存储。

这些阶段在同一个驱动作用域中组合，工作线程和根任务仍由显式 lambda 执行。任务、借用图、矩阵和线程存储的生命周期在驱动中保持可见。

| 模块 | 职责 |
|---|---|
| `core/application.cpp` | 单一核心编译单元与应用组合入口 |
| `core/config/` | 内核编译环境、容量与初始分配参数 |
| `core/preprocess/` | 剥离、根邻域、局部诱导图和顶点对约束 |
| `core/runtime/` | 工作队列、驱动阶段、根任务执行、工作线程和统计 |
| `core/search/search_context.h` | 组合搜索上下文、内核与状态转换 |
| `core/search/context/` | 活动位域、固定基、存储、构造和邻接记账 |
| `core/search/list/` | List 约束、规模上界、分支及终止检查 |
| `core/search/kernels/` | Word64、State64和宽位内核、上下文构建与分派 |
| `core/search/state32/` | State32枢轴、缺边计算、过滤、极大性和批处理 |
| `core/search/folding/` | 入口折叠、固定顶点及局部重物化适配 |

## 搜索上下文

`SearchContext<MaximalityChecker, Emitter>` 维护搜索所需的数据与操作。P是已选择顶点，C是候选顶点，X是排除顶点。固定顶点F仍属于逻辑解，但可以置于活动位坐标之外；规模、可行性、极大性和输出均须考虑P与F。

上下文成员与类内模板方法按职责组织为 `.inc` 文件，由 `search_context.h` 在类作用域中包含。这些文件共享同一对象、类型与成员布局，并非独立的运行时对象。模板内核保持类内定义，便于编译器内联，模块之间不引入虚调用或额外的状态复制。

`core/search/search_types.inc` 定义通用类型与线程统计；`context/`管理状态存储、固定基、邻接记账和位上下文；`runtime/`管理可迁移状态。阅读内核时，可以从对应的 `kernels/` 或 `state32/` 文件进入，再沿其调用查看约束和恢复代码。

## 表示与内核选择

较大的活动域采用List表示，并在合法入口尝试位表示。128/256位入口同时检查容量、固定基条件和完整子树代价，不能只凭候选数决定入口是否合法。List的include子分支保留规模上界；位内核不增加递归贪心上界。

活动域不超过64位时，统一分派：

- 不超过32位的状态进入State32，把多个状态放入AVX2的32位元素中共同执行。
- 33–64位状态在Word64与State64之间选择；State64组合多个64位状态执行。
- 宽位状态由128/256位表示承载，活动域缩小时转换为较窄表示。

`kernels/dispatch64.inc`定义Word64/State64选择及窄位分派。`shared/kernel_selection.h`维护正式的子树代价选择策略；`shared/width_selection.h`管理128/256位入口的在线选择。

State32的公共邻接扫描由`state32/`中的方法执行。同一局部邻接行可用于多个状态的度计算、缺边累计和过滤；每个状态仍按自己的集合关系独立决定分支和候选删除。

## 折叠与重物化

没有外层固定基且活动域为33–64时，入口尝试固定选择通用候选顶点。折叠后活动域不超过32才提交，否则恢复候选成员、顺序和位置索引。

局部折叠保持固定基及极大性见证的完整语义。满足余量条件时，重物化建立较窄上下文，并通过栈池复用工作存储。返回父状态时恢复坐标、集合与固定基。

`search/folding/entry_fold.inc`管理入口提交与回滚；`forced_vertices.inc`管理固定顶点；`local_fixed.inc`管理局部固定基及重物化适配。`core/folding/`提供这些操作使用的约束、折叠和准入组件。

## 任务所有权与极大性

位任务包含恢复所需的完整上下文；List任务可以借用根任务的不可变图与矩阵。借用存储在依赖它的全部后代任务完成后才释放。固定基、坐标映射及外部极大性见证必须随任务迁移。

极大性检查同时考虑局部排除顶点、外部排除顶点与根任务左侧顶点。`output/global_maximality.inc`检查局部解能否被图中其他顶点扩展；最终输出应使用原顶点编号。

共享核心保证使用同一套实现。并行调度和在线代价观测仍可能改变运行顺序及内核选择，不要求顺序与并行拥有相同执行轨迹。

## 正式配置与验证

`config/build_flags.json`保存正式编译选项；`config/runtime.json`保存统一运行参数。公开入口只暴露数据、k、q、执行方式、线程数和CPU绑定。运行脚本显式应用完整正式配置。

输入满足k≥2、q≥2k−1。公共邻居计数采用有符号比较，使q−2k为−1时保持正确含义。

对规模为s的k-plex，每个顶点在解内的度至少为s−k，因此规模至少为q的解只可能包含(q−k)-core中的顶点。迭代剥离不会删除合格解中的顶点，也不会删除能够扩展这些解的顶点。

解内两个非相邻顶点在其余s−2个顶点中，各自至多缺少k−2条邻接，故公共邻居至少为s−2k+2。当s≥q≥2k−1时，该下界至少为1，解内任意两点距离至多为2。相邻顶点的公共邻居下界则为s−2k；在最低合法阈值处为−1，不能转换为无符号整数。

根任务按退化序只枚举以当前根为最早顶点的解。右侧局部顶点使用q对应的公共邻居下界；左侧顶点用于判断能否扩展当前解，使用q+1对应的下界。顶点对约束的计数与阈值同样保留有符号类型，负下界不应被解释为容量或位数。

极大性始终相对于原图。一个外部顶点能够加入当前解，当且仅当它自身满足加入后的度要求，且与当前解中全部饱和顶点相邻。全图检查用上述条件检查根任务左侧见证；局部排除集、固定基与位宽转换也须保留这些见证。

测试按定义穷举小图，对比完整极大解集合，并检查重复、原编号、固定基、位宽、边界和并行结果。验证可执行文件加验证宏单独构建；性能可执行文件使用相同搜索实现，不输出完整解集合。

## 输入与计时

二进制图采用小端32位整数：顶点数n、邻接条目数a、n个度数及全部有序邻接表；总长度为8+4n+4a字节。图须简单、无向，顶点编号从0开始连续。

算法内部时间与外层wall分别记录。输入核对、编译与测试不计入算法时间。工作负载验证输入头部、大小、SHA256、运行配置和期望计数；单次耗时不能代表稳定性能分布。
